# Claude Code runner

## Goal

Run one task: spawn Claude Code headlessly in its worktree, stream and persist the event
transcript, classify the outcome, and show it live. **This is the task that proves the
product works.**

## Why now

It is the riskiest component. Everything after it is scheduling and polish around a loop
that either works or doesn't.

## Scope

**Process (`runner/process.rs`)**

- Spawn:

  ```
  claude -p \
    --output-format stream-json --verbose \
    --session-id <uuid> \
    --permission-mode <mode> \
    [--strict-mcp-config --setting-sources project,local] \
    --append-system-prompt <orchestrator constraints> \
    --model <model> [--effort <effort>] \
    [--disallowedTools ...] \
    [--max-turns <n>]
  ```

  cwd = the task's worktree; composed prompt written to **stdin**, then stdin closed.
- **Environment inheritance** (ADR-0004 amendment): a single app setting,
  `run_environment`, with two modes — `inherit` (default; the operator's MCP servers,
  hooks and plugins, because that is capability worth having) and `strict_local` (applies
  the bracketed flags above). Toggle lives in Settings; no per-repository override.
- **Always strip inherited `CLAUDE_*` env vars**, independent of that setting — they are
  process identity, not user config, and Rimaia is developed from inside Claude Code.
- Record per-run cost from `result.total_cost_usd` and show it: inheriting costs ~3.6× per
  run, and that tradeoff should be visible where the toggle is.
- Verify the `init` event echoes back the `permissionMode` that was requested; treat a
  mismatch as a fatal misconfiguration rather than proceeding.
- Session id generated by Rimaia up front so resume works even if the process dies before
  its `init` event.
- Permission mode from ADR-0012: `bypassPermissions` for queued runs in an opted-in
  repository, `acceptEdits` for a manually started foreground run.
- Cancellation: SIGTERM, grace period, then SIGKILL. Correct process-group handling so no
  orphaned children survive.
- All child processes reaped on app exit.

**Stream (`runner/events.rs`)**

- Parse stdout line by line as newline-delimited JSON. A malformed line is logged and
  skipped, never fatal.
- Handle `system`/`init`, `assistant`, `user`, `result`. **Unknown event types are
  persisted verbatim and ignored** — a CLI update must not break a run.
- Append every line to `<app-data>/runs/<task-id>/<run-id>.jsonl`, flushed as it arrives.
- Maintain a bounded in-memory ring buffer of recent activity and emit Tauri events for
  the live view.
- Capture stderr separately into the same run directory.

**Outcome (`runner/outcome.rs`)**

- Classify the termination into the ADR-0011 classes: `success`, `usage_limit`,
  `transient`, `interrupted`, `fatal`, `cancelled`. For MVP, only `success`, `fatal`, and
  `cancelled` act; the others are recorded so task 014 can act on them without
  re-deriving classification.
- Extract from the `result` event: turn count, cost, duration, error text.
- Extract a PR URL from the transcript when the agent opened one.
- Persist the `runs` row: status, exit class, timings, the exact composed prompt, log path.
- On `success`, move the task to `in_review` and set `run_state = idle`.

**UI**

- "Run now" on a task, disabled with an explanation when the repository has not opted in.
- Runs view: active run with elapsed time, turn count, current tool call, recent assistant
  text, and a Cancel button.
- Task detail shows the last run's outcome and links to its log.

## Out of scope

- The queue (009) — this task runs exactly one task, started manually.
- Retry and resume behaviour (014). Classification only.

## Acceptance criteria

- A task with a real plan produces commits on its branch and reaches `in_review`.
- The live view updates while the run is in progress, and shows the current tool call.
- The complete transcript is on disk as valid JSONL and survives force-quitting the app
  mid-run.
- Cancelling terminates the process within the grace period and leaves no orphan.
- A missing `claude` binary produces a clear, actionable error before any run state is
  written.
- Both `run_environment` modes work: `inherit` connects the operator's MCP servers,
  `strict_local` does not — verified by asserting on the `init` event's `mcp_servers[]`
  and `tools[]`. Fixtures for both already exist as `env-leak-*.jsonl`.
- Inherited `CLAUDE_*` env vars are absent from the child in both modes.
- Prompts several thousand tokens long are delivered correctly via stdin.
- The stored prompt matches what task 006 composes.
- An injected unknown event type does not fail the run.

## Notes

**This is the MVP's proof point.** Before building anything on top of it, run a real task
end to end against a real repository and confirm the branch is something you would review.

The event parser and the outcome classifier are the two pieces most exposed to CLI
changes. Keep both tolerant, and test both against the fixture harness from task 019 —
they must be exercisable without spawning a process or spending tokens.
