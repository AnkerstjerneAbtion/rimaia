# Every prompt input is consented, generated or constrained

## Goal

Make [ADR-0032](../docs/adr/0032-assignment-and-consent-to-run-on-a-machine.md)'s promise
hold for **every** input a composed prompt reads, not only the ones a review happened to find.
Task 045's security reviews found prompt channels one at a time: the title, the links and the
strategy prose (closed in 045 by the 2026-10-10 amendment), then the strategy catalogue's
labels and the repository's name and default branch. This task closes the last two, and
replaces finding channels by review with a rule and a test that fail on the next one.

**The rule** (ADR-0032's amendment "every prompt input has a class"). In a shared team, every
value a composer renders into a prompt, including through a template variable, is one of:

1. **Consent-gated content:** a piece `consent::pieces_for` lists, at a revision the runner's
   owner wrote, accepted or trusts.
2. **Generated by Rimaia:** ids, commit shas, counts, timestamps, run ids, attempt numbers,
   column and state names, and logins (constrained at sign-up, 047).
3. **Constrained on write:** a value validated when it is written, against a charset and
   length that cannot carry a sentence.
4. **None of these:** it is **not rendered** in a shared team. Where a line or a template
   variable needs a value, it gets a class 2 stand-in instead.

**In solo nothing changes.** A personal team's every author is its owner, so every input is
the owner's own. Personal-team prompts stay byte for byte what they are.

## Why now

Before 051, no shared team can have a second member, so none of these channels can reach
anyone's machine yet. From 051 on they can. This task lands first, so a shared team never
exists with an open channel. It comes after 072 because 072 adds the authorship lines, which
this task's test must see.

## Scope

**1. The inventory.** Read every composer in `crates/core/src/runner/prompt.rs` (implementation,
strategy, review, fix, resume, continuation), `task_context`, and template expansion
(`Variables::of` and every `{{…}}` variable). For each value rendered, record its class under
the rule. The inventory goes into the D entry (Scope 5) as a table: value, where it is
rendered, class, and for class 4 the stand-in. Known so far, which the inventory must confirm
or correct:

| Value | Class | Shared-team treatment |
| --- | --- | --- |
| Task title, plan, extra instructions, links, strategy phase prose | 1 | already gated (045) |
| Base instructions, review instructions and override, findings, base commit | 1 | already gated (045) |
| Authorship lines' logins and runner label | 2, and the runner owner's own label | unchanged (072) |
| Strategy catalogue labels (`choices`, planner prompt) | 4 | the planner prompt lists ids only |
| Catalogue model and effort ids | 3 | validated on write (Scope 2) |
| Repository name (`- Repository:` and any variable) | 4 | the line is omitted, and a variable expands to the repository's id |
| Repository default branch (`- Base ref:`, `base_ref`) | 3 | validated on write (Scope 2) |

Anything else the inventory finds in class 4 is treated the same way in this task, and listed.

**2. Constraints on write.** In `rimaia-core`'s services, so every door shares them (ADR-0006):

- **Catalogue ids** (`strategy::catalogue::set_catalogue`): each model and effort id matches
  `^[A-Za-z0-9][A-Za-z0-9._:-]{0,63}$`. They are passed to the agent CLI as argv values
  already, so this narrows nothing that worked.
- **Default branch** (`repo::register`, `repo::update`): a valid branch name by
  `git check-ref-format --branch` (run as an argument vector, no `sh -c`), with no whitespace,
  at most 100 bytes.

A refusal is `Invalid`, with a sentence naming the field and the rule. Existing values are not
rewritten. One whose value would fail is reported by the doctor as a warning naming the field,
and still runs in a personal team.

**3. Rendering in a shared team.** The composers branch on the same fact 045 and 072 use for
"personal team" (`RunContext::authorship` being `None` is not enough on its own; use the
team's kind as 045's personal-team rules do). Class 4 values follow the table's
shared-team treatment. No personal-team string changes.

**4. The canary test.** `a_shared_team_prompt_carries_no_ungated_team_text`: on 045's shared
fixture, set every team-writable text field the inventory lists to a distinct canary string
(`CANARY-<field>`), accept or author every class 1 piece, then compose every prompt kind for a
task in that team. Assert that every canary of a class 1 field appears, and that no canary of
a class 3 or 4 field appears except as its validated value. A team-writable field added later
without a decision appears in a prompt as its canary and fails this test. Add a second case on
the solo fixture asserting that every prompt is byte for byte what it was.

**5. Records.**

- **ADR-0032:** its amendment "every prompt input has a class" already states the rule
  (written before this task). This task adds nothing to the ADR unless the inventory finds a
  value the rule cannot classify. In that case, stop and ask.
- **A new D entry**, "Prompt inputs and their classes", holding Scope 1's table as built.
- **The "How to use this" row** for 073.

## Out of scope

- **New consent kinds or migrations.** Nothing here becomes a new piece; class 4 is handled by
  not rendering.
- **Changing what the UI shows.** The catalogue's labels and the repository's name still show
  everywhere in the interface.
- **Point 6's environment stripping:** 055.

## Acceptance criteria

- Scope 1's inventory is complete and recorded in the new D entry.
- Unit tests for Scope 2's constraints, one per field and rule, through the services:
  `a_catalogue_id_with_a_space_is_refused`, `a_default_branch_that_is_not_a_branch_name_is_refused`,
  and an existing invalid value reported by the doctor and not rewritten.
- `a_shared_team_planner_prompt_lists_catalogue_ids_only` and
  `a_shared_team_prompt_omits_the_repository_name`, asserting whole strings (CLAUDE.md).
- Scope 4's `a_shared_team_prompt_carries_no_ungated_team_text`, and the solo case.
- **Solo is unchanged.** Every pre-existing exact-string prompt test passes with its expected
  string untouched.
- The D entry and the "How to use this" row exist.
- Every CI check passes, exactly as CLAUDE.md lists them.
